# Aevia 产品侧白板能力重构与扩展方案

## 一、总体结论

当前问题不是“再增加几个工具按钮”，而是现有模型把可见内容、绘制行为、变换行为和历史状态都塞进了 `Command`：

- 橡皮是 `destination-out` 画笔，所以它只是按顺序擦除画布像素，本身仍可被选择和变换。
- 移动、缩放通过 `cmd-batch-*` 直接覆盖旧笔迹的 `points`，没有独立操作记录。
- 撤回重做直接修改 `isDeleted`，清屏还会物理删除历史，不是真正的操作日志。
- 全量渲染按扁平点排序，部分脏矩形路径却按命令遍历，不能保证两条路径产生完全一致的像素顺序。
- 工具类型被硬编码成 `"pen" | "eraser" | "cursor"`，新增工具需要修改大量控制器、状态和渲染分支。
- 当前插件系统只有生命周期 Hook，没有工具注册和统一绘制扩展面。

重构后的核心关系应为：

1. `SceneOperation`：不可变、可撤回、可排序的协同操作日志。
2. `BoardElement`：用户可以选择和变换的逻辑元素。
3. `RenderAtom`：笔迹段、字形、形状、贴纸等统一的最小可见单元。
4. `SceneEngine`：按固定顺序折叠操作，产生元素状态、Render Atom、有序索引和脏区。
5. 全量、增量、脏矩形渲染全部消费同一条 Render Atom 流。

失败的未提交 `transform + previousPoints + pathBases` 实验全部作为反例移除，不保留整段点快照覆盖、前后端重复折叠或回写旧命令的逻辑；清理时按代码块精确剥离，保留工作区内限流、actor 生命周期等无关改动，禁止整仓 reset/checkout。

## 二、共享领域模型与协同语义

### 2.1 公共类型

引入统一类型，替换散落的工具联合类型：

- `ToolId = string`
- `ElementKind = stroke | text | shape | sticky-note | sticker`
- `OperationOrder = { lamport, operationId }`
- `RenderOrder = { lamport, operationId, localIndex }`
- `Matrix2D`：页面归一化坐标中的仿射矩阵
- `SceneOperationEnvelope`：包含 `schemaVersion: 2`、ID、页面、作者、Lamport、`roomSeq`、历史分组和具体载荷
- `BoardElementView`：元素类型、有效矩阵、有效边界、是否完成、是否可选择
- `ToolDefinition`：工具元数据、输入方式、默认样式、可用能力和渲染配方

所有比较统一使用：

1. Lamport 升序。
2. ID 字节序。
3. 同一操作内部使用稳定 `localIndex`。

前端、worker 和 Go 后端必须分别使用同语义的共享比较函数，禁止 `localeCompare`、Map 插入顺序或临时数组顺序参与最终结果。

### 2.2 操作种类

- `element.create`
  - 创建笔迹、文字、形状、便签或贴纸元素。
  - 自由笔迹和初次文字输入允许通过现有 start/update/stop 思路流式追加。
  - `stop` 后元素创建操作锁定，服务器拒绝继续修改其历史内容。
- `text.patch`
  - 插入或删除 Unicode 字素，不整体替换文本。
- `element.transform`
  - 保存目标元素 ID 和变换增量矩阵，不保存目标点快照。
- `element.style`
  - 修改颜色、透明度、线宽、线型、填充等属性。
- `erase.cut`
  - 保存被擦 Render Atom 的稳定 ID，以及局部切除区间或遮罩。
- `element.delete`
  - 隐藏指定元素，不删除其创建数据。
- `page.clear`
  - 使用服务器 `roomSeq` 前沿隐藏清屏前的元素，不物理删除命令。
- `history.toggle`
  - 激活或停用一个 `historyGroupId`，不直接修改原操作。

一次长笔迹、一次连续擦除、多对象变换等可以拆成多个协议分片，但共享同一个 `historyGroupId`，因此用户只需撤回一次。

### 2.3 CRDT/并发折叠规则

- 创建、文字字素和可见 Render Atom：按统一 RenderOrder 严格排序。
- 并发变换：按统一操作顺序组合矩阵，所有变换都保留，不使用覆盖式 LWW。
- 并发样式修改：每个样式字段分别采用统一顺序下的 LWW。
- 文字：稳定 `charId + afterId` 序列；同一位置的并发插入按字素 Order 排列，删除使用可撤回 tombstone。
- 删除和擦除：效果并集；撤回其中一个操作不影响其他仍生效的删除或擦除。
- 历史状态：同一历史分组最后一个 `history.toggle` 决定是否生效。
- 清屏：只影响服务器处理清屏前已经存在的元素，之后创建的元素可见。
- `roomSeq` 继续负责持久化、增量重放和因果前沿；Lamport + ID 负责可见顺序。

文档级操作全部进入撤回重做；工具切换、光标、选择框和变换预览属于临时 UI/Presence 状态，不进入历史。

## 三、统一 SceneEngine 与渲染管线

### 3.1 Render Atom

所有工具只能编译成有限的基础原语：

- `stroke-dot`
- `stroke-segment`
- `shape`
- `glyph`
- `bitmap/sticker`

每个 Render Atom 都包含稳定 ID、所属元素、RenderOrder、局部几何、有效矩阵、绘制样式、有效边界和可见遮罩。

现有中点二次曲线、压力宽度、采样、简化和批处理逻辑继续复用，但将“有状态点绘制”拆为：

1. 笔迹编译器把相邻采样点编译成自包含的二次曲线段。
2. 原子光栅器无状态地绘制该段。
3. 增量、全量和局部重绘都调用同一光栅器。

这样局部重绘不再需要按命令回放整段路径，也不会破坏跨命令点级排序。

### 3.2 跨类型复杂层级

- 笔迹首点产生 dot Atom，后续每个采样点产生 segment Atom，并继承该点的 Lamport。
- 文字每个 Unicode 字素产生 glyph Atom，并使用字素插入时的 Lamport。
- 虚线、点划线和双线由同一个 stroke 编译器产生一个或多个具有稳定子序号的 Atom。
- 形状和贴纸是一次创建的原子组；自由绘制预览不进入正式层级，提交后使用创建操作顺序。
- 变换不会把元素自动提到最上层。

验收示例：

- A 开始一条长笔迹并停留。
- B 在笔迹已有部分上逐字输入一句话。
- A 继续画过这句话。
- 旧笔迹段位于字形下方，之后产生的笔迹段位于字形上方；在线双方和晚加入客户端必须得到相同结果。

### 3.3 脏矩形

SceneEngine 维护页面级有效边界索引：

- 新增内容：新 Atom 边界。
- 变换：旧边界与新边界的并集。
- 删除、撤回、重做：操作生效前后边界并集。
- 文字重排：文字元素旧边界与新边界并集。
- 擦除：擦除路径扩张后的范围。
- 清屏：允许整页刷新。

脏区合并继续复用现有队列机制，但候选 ID 只用于空间查询，最终必须重新按 RenderOrder 排序。脏区渲染流程固定为“清除裁剪区 → 查询相交 Atom → 排序 → 使用统一光栅器重放”。

worker 与主线程 fallback 引用同一 SceneEngine、编译器和光栅模块；worker 仅负责消息调度、缓存和 OffscreenCanvas，不再维护第二套 `flattenCommands` 逻辑。

## 四、现有功能重做

### 4.1 真正的橡皮擦

橡皮复用现有采样器和实时传输，但不产生可见画笔元素。

worker 在擦除时：

1. 查询橡皮轨迹下、且在该擦除采样前已经可见的 Render Atom。
2. 对笔迹段生成量化的参数区间切除记录。
3. 对字形、形状和贴纸生成元素局部坐标中的遮罩。
4. 将结果作为 `erase.cut` 分片发送，并立即应用相同结果。
5. 后端只验证目标、页面、数值范围和载荷限制，不重新实现几何算法。

切除记录绑定稳定 Atom ID 和元素局部坐标，因此移动、缩放或旋转后，遮罩和剩余内容一起变换，被擦部分不会重新出现。橡皮没有 `BoardElement`，不能被框选、移动或变换。

为支持撤回，原始几何仍保留在历史数据中，但活跃场景编译时不会产生被切除像素；这不是白色覆盖或画布级 `destination-out` 回放。

### 4.2 选择、移动和变换

选择系统改为查询 SceneEngine，而不是扫描 `path + pen` 命令：

- 点击：从顶层向下做真实几何命中，忽略已擦除区域。
- 框选：查询与框相交的所有可选元素。
- 支持笔迹、文字、形状、便签和贴纸。
- 未完成的实时笔迹暂不可选择，结束后自动进入索引。
- 完全被擦除的元素不可命中，但保留历史供撤回橡皮。

拖动期间：

- 不修改 canonical points。
- SceneEngine 保存独立的本地预览矩阵。
- 通过 droppable Presence 消息发送 `transform-preview`。
- 远端预览有 gesture ID 和超时，断线或取消后自动清除。
- 松手后提交一个 `element.transform` 操作，移除预览。

首期支持：

- 移动。
- 四角缩放。
- 旋转手柄。
- Shift 等比缩放、旋转按 15° 吸附。
- 文字、便签和贴纸默认等比缩放；笔迹和普通形状允许非等比缩放。
- 禁止缩放穿过零点产生翻转，设置最小可见尺寸。

并发用户同时变换同一元素时，双方矩阵按照固定顺序组合；撤回只移除本人提交的矩阵，不覆盖另一人的结果。

### 4.3 撤回重做

移除依赖全局数组下标和物理 `delete-cmd` 的历史分支清理。

HistoryController：

- 只选择当前用户、当前页面的可撤回历史分组。
- 新操作后清空本地 redo 栈，但不删除已停用操作。
- Undo 发送 `history.toggle(active:false)`。
- Redo 发送 `history.toggle(active:true)`。
- 后端验证用户只能切换自己创建的历史分组。
- 页面重载后可继续撤回活跃的本人操作；redo 栈按常规编辑器语义从当前会话重新开始。

连续文字输入按约 750ms、光标未移动且输入类型相同进行历史分组；一次 IME 组合输入是一个分组，连续退格是另一个分组。

### 4.4 清屏与删除

- 删除键提交 `element.delete`，可撤回。
- 清屏提交 `page.clear`，可撤回。
- 后端不再删除被清屏元素。
- 多次清屏分别保留，撤回最近一次只恢复该次隐藏的内容。
- 老版本已经物理删除的数据无法重建，只保证升级后的操作完整可撤回。

## 五、核心产品工具套件

### 5.1 绘制工具

通过统一 `ToolDefinition` 注册：

- 钢笔：保留现有压力和速度模拟。
- 铅笔：使用命令 ID 和采样序号作为种子生成确定性纹理与轻微透明度变化，禁止运行时随机数。
- 荧光笔：固定/弱压力宽度、低透明度、source-over 合成。
- 线型：实线、虚线、点划线、双线。

虚线相位基于累计弧长并保存在 stroke 编译状态中，保证实时追加、分块传输、完整重放和脏区重放视觉一致。

### 5.2 文字

- 点击创建，多行输入，双击重新编辑。
- 支持颜色、字号、粗体和左对齐；首期固定使用随应用打包的字体族。
- 正确处理中文输入法的 composition 事件，只在组合完成后提交字素。
- 使用 Unicode 字素分割，组合 Emoji 不拆成多个字符。
- 每个字素拥有稳定 ID、插入位置、Advance 和 RenderOrder。
- 存储字素 Advance 与行高，布局状态不依赖不同客户端临时测量结果。
- 插入、删除、换行和样式修改均实时协同并可撤回。
- 编辑框只提供光标、选区和输入捕获；正式字形仍由统一画布管线绘制。

### 5.3 形状、便签与贴纸

首期内置：

- 矩形、椭圆、直线、箭头。
- 描边颜色、宽度、线型和可选填充。
- 便签：背景 Shape Atom + 与普通文字共用的字素序列。
- 表情贴纸：使用随应用打包并清洗过的 SVG/位图资源键，避免不同系统 Emoji 字体造成视觉差异。

它们均支持选择、移动、缩放、旋转、擦除、删除和撤回重做。图片上传、对象组合/锁定、连接线吸附和多对象对齐不纳入本轮。

### 5.4 UI

主工具栏由注册表生成，分为：

- 选择。
- 绘制及笔刷/线型菜单。
- 橡皮。
- 形状。
- 文字。
- 便签。
- 贴纸。

选中元素后显示上下文属性栏。`RoomView` 只负责组合控制器，不写具体工具分支。

## 六、插件扩展边界

保留现有 `EditorPlugin` 和 Hook，并扩展 EditorHost：

- `registerTool(definition): dispose`
- `listTools()`
- `activateTool(toolId)`
- 只读的选择状态与工具配置访问
- 受控的 SceneOperation 提交入口

`ToolDefinition` 是可序列化描述，不把函数传进 worker。首期插件只能组合已有输入模式和基础 Render Primitive；需要自定义全新 Primitive 的插件 ABI 留到后续版本化设计。

所有内置工具也必须通过同一注册表接入，以证明扩展面真实可用。工具不能直接访问 Canvas、WebSocket 或 commandStore，避免重新形成工具专属渲染管线。

后端保留动态 JSON 载荷能力，但验证通用操作信封、命名空间、权限和大小；未知渲染配方由客户端明确拒绝，不静默降级。

## 七、协议、后端与旧数据兼容

### 7.1 V2 协议

复用现有 WebSocket、room actor、可靠/实时队列、ack、`roomSeq`、delta replay 和持久化 writer，增加 V2 消息：

- 原子操作提交。
- 流式操作 start/append/commit。
- 历史 toggle。
- 临时 transform preview。
- V2 场景初始化元数据和二进制几何分块。

服务器维护“进行中/已提交”状态：只有进行中的创建或擦除流允许追加，commit 后不可修改。

所有载荷限制同时覆盖 JSON 和二进制路径；写入失败继续触发只读与 resync 机制。

### 7.2 初始化与页面切换

保留“命令元数据流 + 二进制重几何流”的现有基础：

1. 先发送操作元数据、历史状态和元素描述。
2. 二进制分块发送笔迹采样等大数据，并带稳定 Atom/采样索引。
3. worker 合并两条流并逐步构建 SceneEngine。
4. 页面切换沿用 loaded-page window。
5. delta replay 重放原始 V2 操作，不发送派生点快照。

后端不实现第二套文字、擦除或变换几何引擎。

### 7.3 存储和迁移

继续使用现有 commands JSON 表：

- `type` 保存 V2 operation kind。
- 开放流允许 revision 增长。
- commit 后该行不可再被覆盖。
- 清屏和撤回不再删除旧行。
- 不需要重写整个 SQLite schema。

旧房间通过只读适配器加载：

- 旧 pen path → stroke 元素。
- 旧 eraser path → 初始化时按旧顺序编译成不可选择的擦除切片。
- 旧 `isDeleted` → 初始 history active 状态。
- 历史上已经被直接移动后的 points → 作为升级时的基础几何，无法伪造此前不存在的撤回记录。
- 失败实验产生的 `transform + updates/previousPoints` 记录不参与场景折叠，只记录告警和数量，不自动删除数据库数据。
- 旧 clear 已经物理删除的数据不承诺恢复。

握手增加 `sceneProtocolVersion: 2`。旧客户端只能收到明确的升级提示，不能继续向已经启用 V2 的房间发送修改。

## 八、实施顺序

1. **清理反例与建立回归基线**
   - 逐块移除失败 transform 实验，保留无关工作区改动。
   - 为“橡皮后移动露出、变换不可撤回、脏区顺序错误”添加必失败回归用例。
   - 保证清理后现有构建和测试恢复稳定。

2. **SceneOperation、SceneEngine 与统一 Render Atom**
   - 落地 V2 类型、比较器、旧数据适配器和纯操作归约器。
   - 抽出共享笔迹编译器与无状态原子光栅器。
   - 统一 worker、主线程 fallback、全量、增量和脏区路径。
   - 在此阶段保持现有钢笔 UI 可用，先证明像素和性能不回退。

3. **历史、选择与仿射变换**
   - 上线历史分组和 toggle。
   - 重做命中、框选、预览矩阵、移动、缩放和旋转。
   - 删除旧 `cmd-batch-move/update/stop` 持久修改路径。

4. **真擦除**
   - 实现稳定 Atom ID、切除区间和局部遮罩。
   - 接入实时协同、历史、脏区和旧 eraser 适配。
   - 完成“擦除后任何变换均不复原”的验收。

5. **核心产品工具**
   - 依次接入铅笔/荧光笔/线型、形状/箭头、实时文字、便签和贴纸。
   - 工具栏改为注册表驱动。
   - 所有工具使用同一 SceneOperation、Render Atom、历史和选择能力。

6. **兼容发布与性能收口**
   - 先双读旧数据并在测试环境 shadow 计算 Scene hash。
   - 新房间启用 V2，再开放旧房间适配。
   - 最后强制 V2 写入并拒绝旧客户端。

## 九、测试与验收

### 单元测试

- Lamport、ID、localIndex 的跨实现排序一致。
- 相同操作集合以不同到达顺序折叠后 Scene hash 相同。
- 并发移动、缩放、旋转全部组合且可分别撤回。
- 擦除中段后移动/缩放/旋转，切口保持；撤回橡皮才恢复。
- 擦除操作之后创建的 Atom 不受此前橡皮影响。
- 文字并发插入、删除、IME、Emoji 字素和撤回重做。
- 清屏、删除、样式、文字修改和工具创建均可撤回重做。
- 同一 ROI 的脏区输出与完整重放裁剪结果像素一致。
- worker 与 fallback 生成完全相同的 Render Atom 序列。

### Go/协议测试

- V2 操作验证、身份覆盖、payload 限制和二进制限制。
- 已提交流拒绝继续追加。
- history toggle 作者权限。
- storage round-trip、actor 顺序、delta replay、late join 和 page isolation。
- V1 render chunk/旧房间适配。
- 旧客户端对 V2 房间得到明确升级错误。

### 双客户端与 E2E

- 长笔迹与逐字文本交错覆盖。
- 两人同时变换同一元素。
- 擦除后由另一客户端移动元素。
- 撤回/重做同步到在线方和晚加入方。
- 文本、形状、便签、贴纸的选择和变换。
- 断线中途笔迹/擦除自动提交已接收部分，重连后可撤回。
- 操作拒绝时清除本地预览并触发页面 resync。
- 多页切换、清屏撤回和页面隔离。

### 性能

复用现有 10k/50k/100k 点基线并新增：

- 混合笔迹、文字、形状和贴纸场景。
- 小 ROI 脏区重绘。
- 多对象变换预览。
- 连续擦除切片生成。
- 实时文字首字符显示延迟。

验收要求：

- 指针移动期间不得触发完整场景重放或整段点数组复制。
- 原有性能基线不得超出现有回归预算。
- 新能力使用同机同浏览器基线纳入现有报告系统。
- 完整执行前端构建、unit、integration、browser、Go vet/test、E2E smoke 和针对性交互基准。

## 假设与默认值

- 未提交 transform 实验不是可保留功能，相关持久记录也不作为有效业务数据。
- 旧数据必须可继续显示；无法恢复历史上从未记录的变换和已物理删除的清屏内容。
- 本轮不包含图片上传、对象组合/锁定、连接线吸附、多对象对齐和无限画布。
- 首期文字采用实时 Unicode 字素级协同。
- 首期变换包括移动、缩放和旋转。
- 所有文档修改必须进入统一历史；Presence 和未提交预览不进入历史。
