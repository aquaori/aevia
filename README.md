# Aevia - 实时协同白板系统

![Aevia](https://img.shields.io/badge/Aevia-Collaborative_Whiteboard-5e6ad2?style=for-the-badge) ![Vue 3](https://img.shields.io/badge/Vue.js-35495E?style=for-the-badge&logo=vuedotjs&logoColor=4FC08D) ![TypeScript](https://img.shields.io/badge/TypeScript-007ACC?style=for-the-badge&logo=typescript&logoColor=white)

## 介绍

**Aevia** 是一套轻量级的实时协同白板系统。你可以创建或加入房间，与其他人一起绘制、书写和交流；房间内容保存在服务端，重新进入时可以恢复。

系统采用**不可变场景操作 + Lamport 逻辑时钟**的同步模型：客户端把绘制和编辑转换为操作，服务端校验、持久化并分发，各端根据确定性的规则还原场景。前端由 Scene Engine 管理对象、绘制顺序和交互，借助 Worker 和局部重绘降低主线程负担。

---

## 核心架构设计

- **场景操作模型**：当前写入链路使用 schemaVersion 2，包含 `element.create`、`element.append`、`element.transform`、`element.erase`、`element.delete`、`element.style`、`text.patch`、`history.toggle` 和 `page.clear`。操作一经提交不会以相同 ID 覆盖，旧数据通过兼容链路读取。
- **确定性顺序**：场景操作与笔迹点携带逻辑时间戳；涉及相同时间戳的比较由 ID 等稳定字段打破平局。前后端的排序规则需要保持一致，不能依赖语言环境。
- **场景与渲染分离**：Scene Engine 将对象编译为渲染单元，维护空间索引和脏区域；画布更新时按影响范围重绘，选区预览与实际场景共同使用对象数据。
- **有状态服务端**：Go 服务为每个房间维护状态，分配 `roomSeq`，处理页面快照、实时分发、断线恢复和 SQLite 持久化。

## 系统特性

### 协同交互层

- **画笔与图形**：支持画笔、铅笔、橡皮、直线、箭头、矩形、椭圆等工具，并提供颜色、粗细和线型设置；绘制矩形或椭圆时可按住 Shift 约束为正方形或正圆。
- **对象编辑**：支持框选、多选、移动、缩放、旋转与删除；文本可在画布内编辑，便签和贴纸可用于标注。
- **撤销与重做**：按用户和页面维护历史，撤销后产生新操作会清除该历史分支的重做资格，不影响其他用户的操作。
- **多页与实时协作**：支持切换页面、同步协作者光标，以及通过链接邀请其他人进入房间。
- **离屏渲染**：使用 Web Worker 处理画布渲染和场景计算，按脏区域更新画面。

### 会话与状态管理

- **房间会话**：用户通过房间号或邀请链接加入，可为房间设置密码；会话 token 用于后续通信和续签。
- **按页同步**：服务端按客户端当前页面分发数据；加载页面时合并快照和同时到达的实时操作，按操作 ID 去重。
- **断线恢复**：连接恢复时可从已应用的 `roomSeq` 增量续传；初始化与 Worker 处理完成后才推进恢复位置，异常时提示刷新。
- **持久化与故障反馈**：Scene 操作写入 SQLite 成功后才确认；相同操作 ID 的重试可识别，存储失败或只读时会向客户端反馈。离线待发送操作保存在当前页面进程中，刷新或浏览器崩溃后不保证保留。

## 技术栈组成

### 前端

- **框架与语言**：Vue 3、TypeScript、Pinia、Vue Router
- **构建与样式**：Vite、Tailwind CSS、Lucide
- **画布与通信**：Canvas 2D、Web Worker、WebSocket

### 后端

- **运行时**：Go（`apps/backend`）
- **并发与通信**：房间 Actor、WebSocket（`coder/websocket`）、二进制数据帧
- **持久化**：SQLite（`modernc.org/sqlite`）、批量写入与 WAL
- **共享协议**：`packages/shared` 保存前端和测试使用的类型、协议及排序规则；Go 侧维护对应实现。

## 部署与集群调度

Aevia 使用 Monorepo，前端和 Go 后端可以一起启动，也可以分别启动。请准备 Node.js 和 Go，版本要求分别参考项目 CI 配置与 `apps/backend/go.mod`。

```bash
npm install

# 一键启动前后端
npm run dev

# 或分别启动
npm run dev:frontend
npm run dev:backend

# 构建 Go 后端和前端
npm run build
npm run start

# 本地预览前端构建结果
npm run preview
```

开发环境默认前端端口为 `5173`，后端端口为 `4646`。前端单独运行或需要连接其他机器时，可参考 `apps/frontend/.env.example` 配置 `VITE_API_URL` 和 `VITE_WS_URL`；一键启动脚本也支持通过 `AEVIA_PUBLIC_HOST` 指定对外访问地址。生产部署建议使用 Nginx 等服务托管前端静态文件，并代理 API 和 WebSocket。

### 生产环境配置

| 变量 | 说明 |
| --- | --- |
| `APP_ENV=production` | 开启生产环境配置校验 |
| `JWT_SECRET` | 会话和邀请 token 的签名密钥；生产环境必须显式设置 |
| `ALLOWED_ORIGINS` | 允许访问的来源列表；生产环境建议配置明确的来源 |
| `DB_PATH` | SQLite 数据库路径；相对路径以进程工作目录为准 |
| `TRUST_PROXY_HEADERS` / `TRUSTED_PROXIES` | 按实际反向代理部署配置可信代理边界 |
| `METRICS_TOKEN` | `/debug/metrics` 访问令牌；未设置时仅允许本机访问 |

## 会话与安全说明

- 开发环境未配置 `JWT_SECRET` 时使用公开的开发密钥，不适合对外部署；生产环境缺少密钥时会拒绝启动。
- 加入房间后获得有有效期的房间会话 token；邀请链接不携带房间密码，设置密码的房间在加入时仍需输入。
- 房间密码在服务端哈希存储，加入接口对连续认证失败进行限制；WebSocket 握手需要有效的房间会话。
- 默认房间号为 `123123`，可通过 `DEFAULT_ROOM_ID` 调整。对外部署时请结合自身环境配置来源、代理和密钥。

## 原理

### 关键点采集与绘制

绘制时，客户端采集指针的位置、压力和逻辑时间，过滤冗余采样并分批发送。笔迹通过创建和追加场景操作逐步形成，Scene Engine 将它们转换为可绘制的路径；预览、提交和重放共用场景数据。

### 同步与重绘

服务端为房间操作分配递增的 `roomSeq`，用于恢复传输进度；场景中的绘制顺序则按操作和点的确定性排序规则计算。页面初始化通过分块传输历史内容，实时操作可能与快照交错，因此客户端按操作 ID 合并，避免丢失或重复。

移动、擦除、撤销和接收较晚操作时，Scene Engine 根据对象包围盒与空间索引确定受影响区域，再局部重绘。部分擦除使用遮罩保留笔迹未擦除的部分，对象变换时遮罩随之生效。

### 房间 Actor 与存储

每个房间由 Actor 串行处理房间状态变化。可靠消息与实时消息使用不同的队列策略，后端对连接、请求和队列进行限制；SQLite 写入失败时进入相应的降级处理，避免把未持久化的操作当作已确认。
